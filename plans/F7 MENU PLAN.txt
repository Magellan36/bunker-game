A0. How this file works (read before editing)

AdminMenu.gd builds its rows from one array, _row_defs, assigned inside _ready(). Each entry is [section_label, button_text, callback]. A "" section means "continue the previous section" (no new header drawn). _panel_height() auto-computes panel height from the row/section counts, and _reposition_controls() auto-lays the buttons out. This means: to add a button you only add one line to _row_defs and one callback function. Do not touch _panel_height(), _reposition_controls(), or _on_draw().

The file already has these getter helpers — reuse them, do not write new lookups:

func _get_power_manager() -> PowerManager
func _get_player_stats() -> PlayerStats
func _get_water_manager() -> WaterManager
func _get_status_effects() -> StatusEffectsContainer

A4. Add the label formatting helper

Add near _draw_str():

## 100000 → "100,000". Local to this menu — no shared number-format helper
## exists in the project yet, and this is the only caller.
func _format_thousands(value: int) -> String:
	var s: String = str(absi(value))
	var out: String = ""
	var count: int = 0
	for i: int in range(s.length() - 1, -1, -1):
		out = s[i] + out
		count += 1
		if count % 3 == 0 and i > 0:
			out = "," + out
	return ("-" if value < 0 else "") + out

A6. Add the WATER output-doubling callback

Background you need before writing this: in scripts/world/water/WaterHookup.gd, output is not a settable float. It is a tier lookup:

const TIER_DAILY_ML: Array[float] = [3000.0, 6000.0, 12000.0, 24000.0]
var tier: int = 0
func get_daily_output_mL() -> float:
	return TIER_DAILY_ML[tier]

Each tier is exactly 2× the previous one, so "double the output" == "tier + 1". Do it that way. Do NOT add a new multiplier variable to WaterHookup, do NOT make TIER_DAILY_ML non-const, and do NOT touch any file other than AdminMenu.gd. WaterManager and WaterInfoUI both call get_daily_output_mL() live every solve/redraw (verified: WaterManager.gd lines ~493 / ~513 / ~928, WaterInfoUI.gd lines ~370–371), so bumping tier propagates on its own — no refresh/resolve call is needed.

At max tier the button must be a no-op, not a crash (index out of range).

## "2x water output" == tier + 1, because WaterHookup.TIER_DAILY_ML is
## [3000, 6000, 12000, 24000] — each tier is exactly double the last. Bumping
## the tier is therefore the doubling, and it goes through the real upgrade
## data path instead of inventing a debug-only multiplier. Clamped at the top
## tier (no-op there, no error). Nothing needs to be refreshed afterwards:
## WaterManager and WaterInfoUI both call get_daily_output_mL() live.
func _on_hookup_output_double_pressed() -> void:
	var wm: WaterManager = _get_water_manager()
	if wm == null:
		return
	var hookup: WaterHookup = wm.get_the_hookup()
	if hookup == null:
		return
	var max_tier: int = WaterHookup.TIER_DAILY_ML.size() - 1
	if hookup.tier >= max_tier:
		push_warning("[AdminMenu] hookup already at max tier (%d) — output unchanged" % max_tier)
		return
	hookup.tier += 1

A7. Add the three FARMING produce-spawn callbacks

Background: produce items are spawned with the existing static helper in scripts/world/items/FarmProduceItem.gd:

static func spawn_at(parent: Node, base_pos: Vector3, type: String) -> FarmProduceItem

It already adds its own random horizontal jitter and the harvest pop-in tween. type is a PlantDatabase species key. The three requested species all exist in PlantDatabase.PLANT_CONFIG already: "potato", "blueberry", "tomato" — do not add anything to PlantDatabase.gd.

FarmProduceItem is a PickupableItem (RigidBody), so spawn it above the player's head and let it fall, exactly like FarmingShopHelper does for shop purchases.

Add one shared private spawner plus three thin callbacks (one row each):

## Shared spawner for the three FARMING rows. Mirrors
## FarmingShopHelper.spawn_purchased_item()'s positioning exactly (player
## position + 1.8 up, item falls under normal gravity into normal pickup
## rules) — deliberately reusing FarmProduceItem.spawn_at() rather than
## instancing here, so admin-spawned produce is byte-for-byte the same object
## a harvest produces (pop-in tween, jitter, charges, all of it).
## No cash cost — this is a cheat menu, not the shop.
func _spawn_produce(produce_type: String) -> void:
	var player: Node3D = get_tree().get_first_node_in_group("player") as Node3D
	if player == null:
		push_warning("[AdminMenu] no player in tree — produce spawn skipped")
		return
	var parent: Node = player.get_parent()
	if parent == null:
		return
	var base_pos: Vector3 = player.global_position + Vector3(0.0, PRODUCE_SPAWN_HEIGHT, 0.0)
	FarmProduceItem.spawn_at(parent, base_pos, produce_type)

func _on_spawn_potato_pressed() -> void:
	_spawn_produce("potato")

func _on_spawn_blueberry_pressed() -> void:
	_spawn_produce("blueberry")

func _on_spawn_tomato_pressed() -> void:
	_spawn_produce("tomato")
