Move-tool detail worth understanding (no code change needed, but verify it in playtest)
MoveDuplicateTool._move_select() hides a placed object like this:

body.visible = false
for child in body.get_children():
    if child is MeshInstance3D:
        child.visible = false
The second loop only checks direct children and was written for the old flat convention (Bed → MeshInstance3D directly). Under the new model (Bed → VisualRoot → 20 MeshInstance3D nodes), that loop now matches nothing — but it doesn't need to: body.visible = false on the StaticBody3D root already cascades through Godot's built-in Node3D visibility inheritance to hide the entire VisualRoot subtree regardless of nesting depth. The restore (body.visible = true, 3 call sites) works the same way in reverse. This is correct and requires no code change — but it's exactly the kind of thing to explicitly confirm in playtest rather than assume, so it's called out below.

Known cosmetic gap (not a regression, not required to fix here)
GhostPreview._rebuild_ghost_mesh()'s TILE_BED branch still builds a plain symmetric procedural box (unchanged, was always like this — the old placeholder mesh was symmetric too) plus a direction arrow. It does not use the real asymmetric headboard/footboard model, so the build-mode ghost preview won't visually show which end will become the headboard before you confirm placement — only the generic direction arrow hints at "front." This was already true before the reskin (old model had no head/foot distinction at all) so it isn't a new bug, just more noticeable now that the real placed object has a visible asymmetry.
