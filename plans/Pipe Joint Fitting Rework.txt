Plan: Pipe Joint Fitting Rework (Elbow / T-Split / Cross / Straight Remnant)
Target repo: Magellan36/bunker-game (branch main). System: Water (docs/systems/water/README.md). Verification: tools/godot_check.sh must pass before considering this done. Read AI_CONTEXT.md and docs/systems/water/README.md before touching any file.

0. What we're changing and why
Today, every "corner"-role pipe joint (a 90° bend, a T-split, or a "+" crossing) is rendered as one small grey SphereMesh sitting exactly at the corner point (WaterPipeElbow.gd). This looks like a simple ball joint.

We're replacing that with the new textured "bolted flange fitting" models (already committed to main, currently unused by any code):

Scene	Represents	Stub arms baked in (local space)
scenes/world/water/WaterPipeElbowCouplerModel.tscn	2-way 90° bend	local +X, local +Y
scenes/world/water/WaterPipeTSplitCouplerModel.tscn	3-way T-split	local +X, -X, +Y
scenes/world/water/WaterPipePlusCrossCouplerModel.tscn	4-way "+" crossing	local +X, -X, +Y, -Y
scenes/world/water/WaterPipeCouplerModel.tscn	plain straight splice (no bend)	local +Y only (through-axis)
scenes/world/water/WaterPipeSegmentModel.tscn	reference material for straight pipe body	n/a (not instanced, see §6)
scenes/world/water/WaterHookupModel.tscn	full wall hookup replacement	n/a (Phase 2, see §7)
Key fact that makes this tractable: every flange/disc on these fitting models is already baked in ~0.22m from the fitting's own center (matches the requested "short distance away from the corner" — no manual per-disc offset math needed). We are NOT hand-placing individual discs. We are picking one whole fitting scene per joint (based on how many pipes actually meet there) and rotating that single scene so its baked-in stub arms point down the real pipe legs.

1. Design decisions (locked in, do not re-litigate)
Degree-2 perpendicular junction (genuine 90° bend, including a horizontal-run-to-vertical-drop transition) → instance WaterPipeElbowCouplerModel.tscn.
Degree-2 collinear junction (both legs point in exactly opposite directions — a leftover remnant after a T-split's branch was deleted, see §5.1) → instance WaterPipeCouplerModel.tscn (plain straight splice, no bend).
Degree-3 junction (T-split) → instance WaterPipeTSplitCouplerModel.tscn.
Degree-4 junction ("+" crossing) → instance WaterPipePlusCrossCouplerModel.tscn.
Degree-0 or degree-1 (dead end / fully orphaned) → no fitting visual at all (matches current behavior for pipe_joint-role dead ends — do not invent a cap/end piece).
Degree-5+ → should never occur (only 6 axis directions exist and Manhattan routing never doubles up); if it somehow does, log a warning via push_warning() and show no visual rather than crashing.
No manual offset constant is needed — the fittings' own geometry already provides the "short distance from the corner" look. Do not add a second offset on top of the model's built-in one.
Fitting visuals are not given ghost/drag previews this pass (today there is no ghost elbow at all — only straight ghost pipe cylinders during drag). Out of scope — do not add one.
Fitting visuals do not get deconstruct-hover highlighting (set_highlight_delete()) — they never have today, and they still aren't independently deletable; they only disappear via the existing prune_orphan_waypoint() path when every edge touching them is gone. Do not add highlighting.

3. The core algorithm (identical math, reused for every degree)
All pipe routing in this game is strictly axis-aligned (see WaterPipeDrawMode.gd's own header — "Manhattan/90°-only, NO diagonal runs, ever"). That means every leg touching any joint points along exactly one of the 6 world unit directions: ±Vector3(1,0,0), ±Vector3(0,1,0), ±Vector3(0,0,1). This is what makes a single generic algorithm work for horizontal turns, T-splits, "+" crossings, AND horizontal-to-vertical drop transitions, with zero special-casing per scenario.

3.1 Snap each leg to an exact axis direction
## Rounds `dir` to the nearest exact world axis-aligned unit vector.
## Guards against tiny floating-point drift — every real leg direction in
## this game is already exactly one of these six by construction, but the
## downstream logic below does EXACT equality/opposite checks, so noise
## must be removed first.
static func snap_to_axis(dir: Vector3) -> Vector3:
	var ax: float = absf(dir.x)
	var ay: float = absf(dir.y)
	var az: float = absf(dir.z)
	if ax >= ay and ax >= az:
		return Vector3(signf(dir.x), 0.0, 0.0)
	elif ay >= ax and ay >= az:
		return Vector3(0.0, signf(dir.y), 0.0)
	else:
		return Vector3(0.0, 0.0, signf(dir.z))
3.2 Build an orthonormal rotation Basis from 2 known perpendicular directions
Godot's Basis(x_axis, y_axis, z_axis) constructor sets exactly where the LOCAL +X/+Y/+Z unit vectors end up after the rotation (i.e. basis * Vector3.RIGHT == x_axis). Since every one of the new fitting scenes builds its stub arms only in the local X/Y plane (never local Z), we only ever need to decide where local +X and local +Y should point in world space — the third axis (local Z) is derived automatically via cross product and never matters visually (it only ever maps to a fitting's negligible "thickness" direction).

## D1 and D2 MUST be exactly perpendicular unit vectors (already guaranteed
## by snap_to_axis() + the axis-grouping logic below). Returns a Basis
## where local +X -> D1 and local +Y -> D2.
static func basis_from_two(d1: Vector3, d2: Vector3) -> Basis:
	var d3: Vector3 = d1.cross(d2).normalized()
	return Basis(d1, d2, d3)
This ONE function is reused for every degree (2/3/4) — only WHICH two directions get passed in changes.

3.3 Dispatch table (given a list of already-snapped leg directions)
## Groups directions by which world axis they lie on (0=X,1=Y,2=Z), each
## entry {"axis": int, "sign": float, "dir": Vector3}. Since every dir is
## already exactly axis-aligned (snap_to_axis), this grouping is exact, not
## approximate.
static func _axis_index_of(dir: Vector3) -> int:
	if absf(dir.x) > 0.5:
		return 0
	elif absf(dir.y) > 0.5:
		return 1
	else:
		return 2

## Returns {"scene_path": String, "basis": Basis} or {} for degree 0/1 or an
## unsupported/malformed degree (5+, or a degree-3/4 set that doesn't
## actually contain the expected opposite-pair structure — defensive, log
## a push_warning() and return {} rather than crash).
static func pick_fitting(leg_dirs: Array[Vector3]) -> Dictionary:
	var n: int = leg_dirs.size()
	if n < 2:
		return {}

	if n == 2:
		var d1: Vector3 = leg_dirs[0]
		var d2: Vector3 = leg_dirs[1]
		if d1.is_equal_approx(-d2):
			## Collinear remnant — see §5.1. Build a basis whose local +Y
			## (the straight-coupler model's own through-axis) points along
			## the shared line; pick any perpendicular helper for local X.
			var helper: Vector3 = Vector3.UP if absf(d1.dot(Vector3.UP)) < 0.99 else Vector3.RIGHT
			var x_axis: Vector3 = helper.cross(d1).normalized()
			return {
				"scene_path": SCENE_STRAIGHT,
				"basis": Basis(x_axis, d1, x_axis.cross(d1).normalized()),
			}
		else:
			return { "scene_path": SCENE_ELBOW, "basis": basis_from_two(d1, d2) }

	if n == 3 or n == 4:
		## Group by axis, find every axis that has BOTH signs present
		## (a straight-through pair) vs. an axis with only one sign present
		## (a lone branch — only possible/expected when n == 3).
		var by_axis: Dictionary = {}   ## axis_index -> Array[Vector3]
		for d: Vector3 in leg_dirs:
			var ax: int = _axis_index_of(d)
			if not by_axis.has(ax):
				by_axis[ax] = []
			by_axis[ax].append(d)

		var pair_dirs: Array = []      ## one representative Vector3ies per straight-through pair
		var lone_dir: Vector3 = Vector3.ZERO
		var has_lone: bool = false
		for ax: int in by_axis:
			var dirs_on_axis: Array = by_axis[ax]
			if dirs_on_axis.size() == 2 and dirs_on_axis[0].is_equal_approx(-dirs_on_axis[1]):
				pair_dirs.append(dirs_on_axis[0])
			elif dirs_on_axis.size() == 1:
				lone_dir = dirs_on_axis[0]
				has_lone = true
			else:
				push_warning("WaterPipeElbow.pick_fitting: malformed leg set %s" % [leg_dirs])
				return {}

		if n == 3 and pair_dirs.size() == 1 and has_lone:
			return { "scene_path": SCENE_TSPLIT, "basis": basis_from_two(pair_dirs[0], lone_dir) }
		if n == 4 and pair_dirs.size() == 2 and not has_lone:
			return { "scene_path": SCENE_CROSS, "basis": basis_from_two(pair_dirs[0], pair_dirs[1]) }

		push_warning("WaterPipeElbow.pick_fitting: unexpected leg structure %s" % [leg_dirs])
		return {}

	push_warning("WaterPipeElbow.pick_fitting: unsupported degree %d" % n)
	return {}

func rebuild_visual(leg_dirs: Array[Vector3]) -> void:
	if _fitting_instance != null and is_instance_valid(_fitting_instance):
		_fitting_instance.queue_free()
	_fitting_instance = null

	var picked: Dictionary = pick_fitting(leg_dirs)
	if picked.is_empty():
		return   ## degree 0/1, or a malformed/unsupported set — no visual, see plan §1.5/§1.6

	var scene: PackedScene = load(picked["scene_path"])
	if scene == null:
		push_warning("WaterPipeElbow.rebuild_visual: failed to load %s" % picked["scene_path"])
		return

	var instance: Node3D = scene.instantiate()
	add_child(instance)
	## Position stays at this WRAPPER node's own global_position (set once,
	## at spawn time, by whichever call site created this WaterPipeElbow —
	## never touched here). Rotation lives on the CHILD instance's LOCAL
	## transform — same split WaterPipeSegment.gd already uses for its own
	## _mesh_instance child (wrapper = position only, child = rotation).
	instance.transform = Transform3D(picked["basis"], Vector3.ZERO)
	_fitting_instance = instance

## Rebuilds every "corner"-role node's joint-fitting visual from its
## CURRENT edge degree/directions. Call once after ANY pipe-graph mutation
## finishes — see docs/systems/water/README.md for the exact trigger-point
## list (mirrors recompute_flow_directions()'s own call sites exactly,

## Self-healing: spawns a WaterPipeElbow for any "corner" node that
## doesn't already have one.
func refresh_all_pipe_joint_visuals() -> void:
	var elbow_script: GDScript = load("res://scripts/world/water/WaterPipeElbow.gd")
	var scene_root: Node = get_tree().get_first_node_in_group("main_world")
	if scene_root == null:
		scene_root = get_tree().get_root()

	var existing_by_key: Dictionary = {}
	for node: Node in get_tree().get_nodes_in_group("water_pipe_elbow"):
		if is_instance_valid(node):
			existing_by_key[node.get("node_key")] = node

	for key: String in _graph.get_nodes():
		var node_data: Dictionary = _graph.get_nodes()[key]
		if node_data.get("role", "") != "corner":
			continue

5. Known edge cases — handle explicitly, don't skip
5.1 Degree-2 collinear remnant
If a player deletes the branch leg of a T-split (or one arm of a "+" crossing down to degree 2), the remaining two legs on that same "corner" node can end up collinear (pointing in exactly opposite directions — no longer a real bend). pick_fitting() already detects this (d1.is_equal_approx(-d2)) and swaps to SCENE_STRAIGHT automatically. No extra code path is needed beyond what's in §4.1 — this is called out here only so the implementing agent understands WHY the straight-coupler branch exists and doesn't remove it as "dead code."

5.2 Degree drops to 1 (dead-end remnant of a former bend)
If a corner drops to degree 1 (one leg deleted, one remains), pick_fitting() returns {} (degree < 2) and rebuild_visual() shows nothing — matches how ordinary pipe_joint-role dead ends already look (no fitting). The node itself is NOT deleted/reclassified (pre-existing behavior, unchanged by this plan — prune_orphan_waypoint() only fires at degree 0). This is an accepted, pre-existing gap; do not attempt to fix it as part of this task.

5.3 Two elbow-branch shapes read identically depending on edge-registration order
get_edges_touching() doesn't guarantee a stable order, so which leg gets treated as "D1" vs "D2" in basis_from_two() for a given elbow is arbitrary run-to-run. This is harmless — both fitting models are symmetric between their two/three/four stub arms (same stub+flange+bolt shape on every arm), so any valid assignment looks correct. Do not add any "stable ordering" logic — it's unnecessary complexity.

5.4 Purifier nodes are untouched
"purifier"-role graph nodes are explicitly skipped by refresh_all_pipe_joint_visuals() (if node_data.get("role","") != "corner": continue). WaterPurifier.gd owns its own dedicated visual entirely separately — do not touch WaterPurifier.gd's mesh-building code, only its revert_to_corner() call site per §4.3/§4.4.
